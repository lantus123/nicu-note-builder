# NICU Note Builder

馬偕新生兒科（NICU）快速產生 note 的線上工具。**點選式（選擇題）結構化組裝** → 即時預覽 → 一鍵複製貼回 HIS。

四個分頁，共用上方基本資料（填一次全帶）：

| 分頁 | 內容 |
|------|------|
| **Admission** | 出生摘要、母體背景、產程與入院經過的敘述式段落；自動 AGA/SGA/LGA（Fenton 2025）＋暫定診斷清單 |
| **NI plan** | 依週數＋admission 選擇自動組出 Diagnostic／Therapeutic／Prognostic 三段計畫 |
| **Acceptance** | 沿用出生資料產生敘述式 Brief history；Hospital course 依呼吸及感染問題串接，ABG 貼上自動判酸鹼；目前體重另填 |
| **Procedure** | 勾選 8 種 procedure（intubation／A-line／LISA／LP／UAC／UVC／chest tube／exchange transfusion），依體重自動帶 ETT size・深度・劑量等 |

## 設計原則

- **純前端、單檔 HTML**：所有計算與組稿都在瀏覽器完成，不送任何後端。
- **病人資料一律不上雲端**：本工具不儲存病人資料；預覽可編輯、複製後貼回 HIS。
- **點選優先**：平常無 risk 幾乎不用點；有陽性才展開子選項。任何組合都組得出通順句子。
- **即時預覽可編輯**：手動改字會鎖住不被覆蓋（琥珀色），可「↺ 重新產生」。
- **敘述保留事實**：採美式英文；按已記錄的時間與問題銜接，不替未填欄位補上治療、改善或因果。檢驗解析器回報未解析的行會保留原文供核對。
- **文法與時態**：時間單位依數值使用單複數；處置紀錄與後續追蹤計畫分開，換血步驟維持計畫式指令。校正的是自動組稿文句，不擅自改寫使用者貼上的原始報告。
- **產前檢查敘述**：已有羊穿 aCGH 結果而沒有 NIPT 結果時，只寫 aCGH 結果，不另補「NIPT 未做」；兩者都有結果時先寫 NIPT，再接 aCGH，不推定檢查先後、因果或結果互相證實。表單順序與已填結果保持不變。

## Admission 出生到入院（原第 5＋6 區，2026-09-20 起為一條時間線）

住院醫師反應第 5／6 區（產房／刀房、急救、standby、嬰兒室或 NBC、外接）不知道怎麼填。9/19 實看畫面：第 5 區預設收合、第 6 區全開且「直接入院」預選；表單按資料模型的軸切，住院醫師腦中卻是一句故事。改成**先選故事、再沿時間線填**：

- **四張故事卡**：A 產前 standby 直接入院／B 出生後會診直接入院／C 嬰兒室觀察後轉入／D 外院外接。**C 的劇情（Ryan 2026-09-20）**：先到嬰兒室（英文一律 baby room，不用 nursery）→ 有狀況（症狀持續超過 24 小時）或有母體風險（第 2 區的發燒／PROM 時數／GBS 陽性自動帶入）→ 兒科去看，**不是會診**（note 寫 asked to evaluate）→ 在嬰兒室抽血（CBC/DC、CRP、B/C、血糖、CXR）→ 結果異常（bandemia、白血球↑↓、CRP↑ 含值、低血糖含值、CXR 異常）才收，結語改用 therefore。沒勾結果只寫做了檢查、不寫成正常；無異常需明確勾「結果無異常（確認）」，且與異常項互斥。所以故事 C 不開「出生後會診」；真的有正式會診再到「調整細節」開。故事卡只是設定既有三個開關（`pathway`／`pwStandby`／`pwConsult`）的組合；混合情況在最下面「調整細節」直接調開關，再點一次已選的故事可取消。
- **一條直的時間線**：選了故事才出現，站別依路徑排序（`order`），例如 C 是「出生當下 → 產房處置 → 產房結束時 → 嬰兒室 → 會診 → 入 NBC」、D 是「外院出生 → 外院產房處置 → 外院產房結束時 → 外院處置 → 外院會診我方 → 我方抵達外院 → 轉送 → 入院」。每一站卡頭一句白話說「這裡填什麼、什麼時候可以空著」。
- **填過的站自動收成一行摘要**（`出生當下 · 有哭聲 · 良好`），只有「現在填這站」展開；點站名可手動展開／收合。摘要是唯讀的，不是第二份紀錄。
- **控制項與資料模型完全不變**：所有欄位 id／`data-*`、`switchPathway` 的路徑草稿、`timelineReview` 的 continuity 提醒都沿用；只是換了父層與顯隱。原「承接產房紀錄」卡與「回第 5 區修改」按鈕退役——同一件事現在由收合摘要承擔。
- 頁面規則：**一區一卡、卡內不再有卡**，分層用線、間距、收合。

## Admission 出生經過與入院路徑

- 表單保留手寫 chart 的區塊順序；第 5 區依「出生觀察 → 實際處置／再評估 → 產房最後狀態」填寫，輸出仍是完整英文敘述。
- PPV、插管、胸外按壓與 epinephrine 分別記錄，不再由急救階梯推定其他處置；新增實際處置即確認有施作，不必先切換狀態。再評估可獨立記錄，反覆事件可調整順序及復原剛移除的項目。
- 第 6 區承接唯讀產房摘要，再選直接入院、嬰兒室觀察或外院轉入；standby 與出生後會診分開選，可與路徑並存。
- 支持延續需明確確認；症狀區分新出現、持續或再次發生。未記錄不當成正常、未施作或已改善，FD／DOIC／MSAF 的陰性敘述需額外確認。
- 切換路徑保留本次開頁草稿，不把其他路徑隱藏資料混入病歷；Acceptance 接手當下支持仍獨立記錄，不被出生／轉送歷史覆蓋。
- **入院路徑不預設**（2026-09-19）：以前「直接入院」預選，零點擊就會寫出入院路徑；現在未選時第 6 區摘要顯示「尚未選路徑」，結語只寫「admitted to …」不寫路徑。再點一次已選的路徑可取消。
- **入院去處在第 1 區選 NICU／NBC／BR**，整份 note 一次選；Admission 結語、入院時狀況句與 Acceptance 都跟著寫 `our NICU`／`our NBC`／`our baby room`，未選時寫成 `____`。
- **產房／刀房由生產方式自動決定**：NSD 寫 delivery room、C/S 寫 operating room，用於 standby 句、產房再評估句、Acceptance 的 surfactant 句；會診句只在明選「直接入院」時才加地點（嬰兒室路徑的會診地點不是產房）。
- 新欄位的用途、跨分頁範圍與刻意排除的資料見 [Admission 欄位對照](docs/admission-field-map.md)。這份對照涵蓋本次時間線改版，不代表全專案歷史欄位已完成全面稽核。

## 填寫介面

- 保留既有區塊順序與完整敘述式輸出；出生／路徑組稿依上述時間線整理，不改動臨床計算或用藥規則。
- 桌面左側填寫、右側預覽；手機預覽預設收合。放大字級、明確的選取與鍵盤焦點，減少重複框線。
- 篩檢直接選擇結果，窄畫面使用原生選單。Rubella「未提及」是中性狀態，不當成陰性。
- 空值本來就合法的單選（性別、生產方式、入院去處、入院路徑、各段呼吸支持與裝置）再點一次已選項目＝取消，手機誤觸不必重整頁面；有語意預設的單選（生長分級、日齡、超音波、產檢）維持不可清空。
- 分頁記住本次開頁的捲動位置，滑鼠／觸控切回時可接續原欄位；鍵盤方向鍵定位分頁，Enter／Space 啟用。可收合區塊也支援鍵盤操作。
- 預覽可切換閱讀／校閱模式與三段字級；這些只改顯示，不改病歷文字。更新時保留預覽位置並短暫標示變動文字，手改鎖定機制維持不變。
- 手機收合後複製仍保留手改換行；複製結果另列提示，不把按鈕擠寬。底部留白隨預覽工具列高度調整。
- 上述位置與預覽偏好只存在本次開頁記憶體，重新整理即重設，不新增病人資料儲存。
- 「本院區」只列台北、淡水、新竹、台東，並在此瀏覽器記住選擇；出生院所、產檢地點與轉入來源另用完整院所清單。舊版若曾把其他醫院存成本院區，不再套用該值。

## 檔案 / 建置
- `index.html` — GitHub Pages 部署檔（standalone 完整 HTML，直接開即可用）。
- `_demo_structured.html` — 本體原始碼（body-only，供 Artifact 預覽與編輯）。
- `lab-parse.js` — **共用檢驗/血氣貼上解析器（單一真相）**。原始邏輯來自 `~/nbc-note-app`（病程記錄 App）的 `doLabParse`。Acceptance 分頁的「Other (CBC/DC, CRP…)」欄貼上血檢報告後即用它整理成一行（WBC/DC、Hb、PLT、電解質、腎肝、CRP… 並自動附 I/T ratio）。
- **建置**：`index.html` = HTML 外殼 ＋ `_demo_structured.html`。`lab-parse.js` 的核心函式以 `//__LABPARSE_START__` / `//__LABPARSE_END__` 標記內嵌進 `_demo_structured.html` 的主 IIFE（維持單檔自足）。改動請編輯 `_demo_structured.html`，再重新產生 `index.html` 後 push。
  - ⚠ **改解析邏輯請改 `lab-parse.js`**，再重新內嵌回兩邊（本 app 與 nbc-note-app），勿在各 app 內各自修改而讓兩份漂移。

> **零病人資料**：本 repo 只放程式碼＋README。設計規格、含真實個案的範例（病歷號／院所／個案細節）一律只留本機、不進版控。連 placeholder 都用假值（病歷號 `00000000`）。

## 本機開發
瀏覽器直接開 `index.html` 即可，無需建置環境。

修改 `_demo_structured.html` 後執行 `bash build/build.sh`；`bash build/build.sh --check` 檢查部署檔同步。
在 `tests/prose` 執行 `npm ci`、`npm test`，驗證敘述快照與欄位輸出、手改保護、時間單位文法、Procedure 的已完成／計畫時態，以及篩檢選取、分頁／收合操作、預覽顯示與複製。刻意調整文句時，可用 `npm run update` 更新快照，再檢查 diff；快照使用固定日期，所有案例均為假資料。
