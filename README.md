# NICU Note Builder

馬偕新生兒科（NICU）快速產生 note 的線上工具。**點選式（選擇題）結構化組裝** → 即時預覽 → 一鍵複製貼回 HIS。

四個分頁，共用同一份出生與入院背景；不同時間的評估分開記錄：

| 分頁 | 內容 |
|------|------|
| **Admission** | 出生摘要、母體背景、產程與入院經過的敘述式段落；自動 AGA/SGA/LGA（Fenton 2025）＋暫定診斷清單 |
| **NI plan** | NBC／NICU 依週數＋admission 選擇自動組出 Diagnostic／Therapeutic／Prognostic 三段計畫，早產醫囑**依出生週數／體重細分**（ROP、腦超、echo、PN、caffeine、預後分層）並自動換算日期；未選去處或 PICU 專用模板尚未確認時，不產生 plan |
| **Acceptance** | 沿用出生資料產生敘述式 Brief history；Hospital course 依呼吸及感染問題串接，ABG 貼上自動判酸鹼；目前體重另填 |
| **Procedure** | 勾選 8 種 procedure（intubation／A-line／LISA／LP／UAC／UVC／chest tube／exchange transfusion），依體重自動帶 ETT size・深度・劑量等 |

## 設計原則

- **純前端、單檔 HTML**：所有計算與組稿都在瀏覽器完成，不送任何後端。
- **病人資料一律不上雲端**：本工具不儲存病人資料；預覽複製後貼回 HIS。
- **點選優先**：常用事實可選取，陰性須明確確認，未填不等於沒有。依已選問題展開相關欄位，保留必要的自由補充。
- **即時預覽唯讀**（Ryan 2026-09-24 拍板）：預覽不可在頁面上手改，永遠跟著表單重組；要修改請複製到 HIS 再改。
- **敘述保留事實**：採美式英文；按已記錄的時間與問題銜接，不替未填欄位補上治療、改善或因果。檢驗解析器回報未解析的行會保留原文供核對。
- **文法與時態**：時間單位依數值使用單複數；處置紀錄與後續追蹤計畫分開，換血步驟維持計畫式指令。校正的是自動組稿文句，不擅自改寫使用者貼上的原始報告。
- **產前檢查敘述**：已有羊穿 aCGH 結果而沒有 NIPT 結果時，只寫 aCGH 結果，不另補「NIPT 未做」；兩者都有結果時先寫 NIPT，再接 aCGH，不推定檢查先後、因果或結果互相證實。表單順序與已填結果保持不變。

## Admission 順向填寫（2026-10-02）

**先選本次情境，再依 chart 順序填產前與出生，最後完成本次病程。** 輸入分區是為了方便操作，輸出維持完整英文敘述。

- 頂層先選直接入院、嬰兒室觀察後轉入、外院轉入或 E 出院後再次就醫；E 同時選門診／急診／預約來源及問題。A/B 的 standby／出生後會診在出生段依實際經過選，不推定團隊介入。
- 情境卡常駐顯示代號、用途與流程，手機也不隱藏；A/B 的出生介入選項同樣保留說明。
- 入院日預設寫病歷當天，顯示唯讀摘要，平常不用填。只有回補日期或補記入院時間才展開「回補病歷／補入院時間」；收起後仍顯示實際採用的日期與已填時間，不會把回補日期改回今天。
- 固定導覽：**1 入院設定 → 2 產前 → 3 出生 → 4 本次病程 → 5 核對**。導覽顯示目前章節及子階段，可展開跳到其他段；母親資料、日期、Apgar 等每項只有一個可編輯來源，E 不必切換其他情境才能補出生觀察與處置。
- E 縮為三階段：**出院與返家基準 → 症狀與變化 → 評估與收治**。固定工作區顯示第 n／N 階段；輸入不自動換段，返回時保留草稿、焦點與相對捲動位置，不以「完成」暗示已做醫療核對。
- 八組 E 模組：黃疸、呼吸症狀、發燒、進食／體重變化、apnea／cyanosis、腸胃症狀、篩檢／檢驗異常、照護需求。只顯示已選問題的欄位；多問題共用奶量、尿量、活動力及起始時間，不同時間才另外補。純呼吸問題不要求 bilirubin，純照護／篩檢不要求發病時間。
- 未填、不詳與確認無分開；母親病史可明確批次確認，未操作不自動生成陰性。任何治療／改善／因果仍需實際記錄。
- 進食模組的每餐奶量只填一次，下方改為唯讀增減摘要與選填的其他進食觀察。舊快捷描述與數值一致時合併輸出、仍保留原值；相反時明確提醒，須由醫師修改或明按移除，可復原。不推斷任意自由文字的語意。
- 路徑與模組切換保留當次開頁草稿，但隱藏的非作用中資料不混入 Admission／Acceptance。核對區分「關鍵資料未填／已記錄待確認」「前後不一致／格式需核對」與中性的「其他選填未記錄」；選填空白不增加複製警告。

## Admission 出生經過與入院路徑

- 表單保留手寫 chart 的產前／出生順序；出生區依「出生觀察 → 實際處置／再評估 → 產房最後狀態」填寫，輸出仍是完整英文敘述。Admission 與 Acceptance 的產房段**同一個順序**：出生觀察 → Apgar → （故事 B 的產房會診句）→ 實際處置 → 再評估（9/20 順八個情境時發現兩份 note 把 Apgar 放在段首／段尾不一致、會診句寫在急救之後與時間線矛盾，已統一）。會診時間晚於第一個處置的分鐘數時，時間線核對會提醒。
- **DOL 定義統一為出生當天 DOL 1**。「自動計算」預設選取且始終可見，入院日期預設今天，只填出生日期即可計算 `DOL = 日期差 + 1`；「今天入院」可將日期設回今天並恢復自動。回補病歷會依指定入院日計算，日期選擇器的 input／change 都會更新。「手動填寫」才顯示日齡按鈕，與日期不一致時提示，可切回自動。PMA 加的是實際經過天數 `DOL - 1`；Admission 使用 `on day of life N`，Acceptance 表頭使用 `DOL N`，不把 DOL 數字誤當英文 chronological age。
- **E 的條件欄位與輸出同步**：只有勾選 neonatal／prolonged jaundice 才顯示 bilirubin，且只填已有檢驗；單純呼吸症狀不顯示。取消黃疸後，先前輸入的黃疸日齡、尿便顏色和 bilirubin 留作草稿，不進 Admission、Acceptance 或階段摘要。所有 `hidden` 欄位都確實隱藏，不受 grid／flex 排版覆蓋。
- **E 的體重標明時點**：本次評估體重只填一次，Acceptance 預設唯讀引用並標明來源；有重新測量時可選「有重新測量」另填，不覆寫入院評估，也不拿出生體重代替現在體重。
- 日期、DOL、前次出院日、症狀起始 DOL、入院來源及路徑資料會做跨區一致性檢查；有矛盾時只提醒，不自行覆寫或捏造臨床事實。
- PPV、插管、胸外按壓與 epinephrine 分別記錄，不再由急救階梯推定其他處置；新增實際處置即確認有施作，不必先切換狀態。再評估可獨立記錄，反覆事件可調整順序及復原剛移除的項目。
- **產房急救 PPV 依 NRP 第 9 版（2025 AHA/AAP，2025-10 發布）預設帶入**（Ryan 2026-09-20）：新增 PPV 事件時依 GA 帶入 PIP（≥32 週 25、<32 週 20 cmH₂O）、PEEP 5、FiO₂（≥35 週 21%；<35 週一律 30%——指引 32–34 週為 21–30%、<32 週 ≥30%，Ryan 定「指引可 30% 就統一 30%」）；通氣率 30–60/min 不寫入。帶入的值以虛線框＋提示標示「NRP 預設，請核對」，並在核對提醒列出；醫師改任一值即視為實際紀錄。沒改就照值寫進病歷——這是 Ryan 明示接受的預設，是「預設值不寫成事實」原則的唯一例外。插管、course 範圍的 PPV 不帶預設。所有 NRP 數值與句型集中在程式的 `NRP` 表（來源：AAP 第 9 版科學變更表的 OPQIC／pw.live 整理），院內教材若不同只改那一張表。
- 急救事件的英文句型對齊 NRP 用語（`positive-pressure ventilation (PPV) was initiated`、`endotracheal intubation was performed and ventilation was continued through the endotracheal tube`、`chest compressions were initiated`、`epinephrine … was administered`）；不自動補入未記錄的比例、劑量或間隔。第 9 版把 PPV 改稱 ventilation，病歷仍保留 (PPV) 以免歧義。
- 入院路徑已在最上方選定，後續病程承接唯讀出生摘要，不重新問一次出生經過；standby 與出生後會診屬於出生事件。
- 支持延續需明確確認；症狀區分新出現、持續或再次發生。未記錄不當成正常、未施作或已改善，FD／DOIC／MSAF 的陰性敘述需額外確認。
- 切換路徑保留本次開頁草稿，不把其他路徑隱藏資料混入病歷；Acceptance 接手當下支持仍獨立記錄，不被出生／轉送歷史覆蓋。
- **入院路徑不預設**（2026-09-19）：以前「直接入院」預選，零點擊就會寫出入院路徑；現在未選時路徑摘要顯示「尚未選路徑」，結語只寫「admitted to …」不寫路徑。再點一次已選的路徑可取消。
- **本次住院去處為 NBC／NICU／PICU**（2026-10-02 院內規則），最上方選一次，Admission 結語、入院時狀況句與 Acceptance 共用。BR 是健康新生兒照護，不列為住院去處；C 仍保留「先在 BR 照護、後來因病收入病房」的經過。
- **E 只允許 NBC／PICU**，已返家的寶寶不收入 NICU。選 E 後 NICU 隱藏且停用；原有不相容去處會明確提示並取消，不自動代選。未選／不相容值只輸出 `____`，不輸出無效的單位。各路徑保存自己的去處草稿；切回時恢復原值並再次驗證，不覆蓋其他路徑的選擇。
- **產房／刀房由生產方式自動決定**：NSD 寫 delivery room、C/S 寫 operating room，用於 standby 句、產房再評估句、Acceptance 的 surfactant 句；會診句只在明選「直接入院」時才加地點（嬰兒室路徑的會診地點不是產房）。
- 新欄位的用途、跨分頁範圍與刻意排除的資料見 [Admission 欄位對照](docs/admission-field-map.md)。這份對照涵蓋本次時間線改版，不代表全專案歷史欄位已完成全面稽核。

## NI plan 讀 admission 的哪些東西（2026-09-23）

- **去處決定配置**：`allowedDestinations()` 統一路徑限制，`DEST_PLAN` 統一 plan 配置。`NBC` 維持**非加護病房配置**：不寫 Giraffe、不寫 Minimize handling、A-line 不因插管自動列入。`NICU` 維持原加護配置。未選／無效去處不再回退為 NICU；`PICU` 在專用院內模板確認前不產生 NI plan，控制項收起，`#planWarn` 說明原因，Admission／Acceptance 仍可使用。提示只進 UI，不進複製病歷。**此變更不新增 PICU 治療規則或劑量；NBC 細項仍待 Ryan 校正。**
- **呼吸狀態依時點取用**：NI plan 優先讀 `S.resp`（入院時支持）；A–D 未填時才沿既有入院前／轉送、出生支持來源判斷。E 不使用多日前的出生支持，Acceptance 的呼吸病程也不再倒推 Admission。既有治療門檻與劑量未在此次修改。
- **嬰兒室抽血結果進 plan**：`brFindings` 出現 bandemia／白血球↑↓／CRP↑ 就算感染風險（自動 empirical 抗生素）；低血糖進 Dex 指徵。`brWorkup` 已抽過的項目不再重開——plan 改寫成「Obtain the remaining sepsis work-up, including …（… were obtained in the baby room）」。
- **入院與接手支持各自獨立**：`S.resp` 描述入院時；`S.acceptanceResp` 描述接手當時。只有明按「已確認接手時與入院時相同」才複製一次，之後互不覆寫。Admission 的支持與入院狀況仍可合成一句。
- **暫定診斷四處同源**：DX chip、Admission 入院結語、Acceptance 入院原因、NI plan 全部讀 `admissionProblems()`／`primaryDx()`。以前三套各自推導，chip 有 Hypoglycemia 而結語與 acceptance 寫 `____`。
- **Procedure 與 admission 的連動（2026-09-23）**：A–D 的 Admission 記錄了我方插管（產房事件、後續事件、或轉送途中新插管）時，Procedure 的「Intubation」自動勾選並顯示提示；手動點過一次就交給使用者，不再自動；E 出生史中的插管不自動當成本次 Procedure。ETT 尺寸依 NRP 現行表（<1000 g 2.5、1000–2000 g 3.0、>2000 g 3.5）。各 procedure 模板的「[Complications] None」為 Ryan 拍板保留的預設。

## NI plan 依出生週數細分（2026-09-24）

以前只有「早產（<37 週）與否」一個開關：34 週和 24 週拿到一模一樣的 ROP／腦超／echo／PN 四條，晚期早產被開了用不到的檢查，極早產又少了 caffeine。現在改成**依出生週數與出生體重分流**，門檻集中在程式裡 `renderPlan()` 前面的 `PLAN_GA` 這張表——**院內 protocol 不同就改這裡，別去改各條規則的行內數字**：

| 規則 | 門檻 | 產出 |
|------|------|------|
| ROP 篩檢 | GA ≤30 週或 BW ≤1500 g | 首檢日＝生後 28 天與 PMA 31 週**取較晚者**（AAP 2018／台灣兒科醫學會） |
| 腦部超音波 | GA <32 週或 BW <1500 g | 第 7–10 天各一次、PMA 36 週再一次；不符條件就整條不寫（晚期早產不再列） |
| hsPDA 心臟超音波 | GA <30 週 | 文字同舊版 |
| PN | GA <34 週或 BW <1800 g，或已插管 | 文字同舊版 |
| Caffeine | GA <34 週 | 排在呼吸支持之後、surfactant 之前；續用到 PMA 34 週且 5–7 天無 apnea |
| 預後併發症監測 | <32／32–33+6／34–36+6 三段 | 分別寫 prematurity／moderate prematurity／late prematurity，足月不寫 |

- **日期會自動算出來**：填了「出生日期」就在括號裡附上日曆日（生後第 n 天、或 PMA 目標週數換算的那一天），沒填就只留「at 4 weeks of age or a PMA of 31 weeks」這類相對說法，**不掰日期**。日期走的是跟 note 其他地方同一個格式器，所以勾了**民國紀年**（最上方設定）plan 的日期也跟著變 `115/8/29`。
- **GA 沒填（gw=0）時四條 GA 規則一律不觸發**，維持既有的「以足月組稿」行為，`#planWarn` 的中文提醒照舊；BW 沒填時 BW 規則同樣不觸發。
- **四條都可以手動覆寫**：「醫囑項目」新增 `Caffeine`／`ROP 篩檢`／`腦部超音波`／`心臟超音波` 四顆按鈕，點一下關掉或強制打開，按「↻ 全部回自動」全部回規則預設（跟既有 sepsis／PN／OG 那幾顆同一套機制）。
- 驗收在 `tests/prose/plan-ga.js`（8 條，含日期換算、民國紀年、開關、GA／生日空白）。

## 家庭樹（Pedigree）（2026-09-23）

Admission note 結尾的 `Pedigree:` 之後接一棵純文字家庭樹，直接貼進 HIS。HIS 是記事本式的純文字、等寬環境，**對齊只能靠空格**，所以渲染器把符號放進「欄位畫布」，再依每個字元的顯示寬度補 ASCII 空格、去掉行尾空白。

- **只有符號一種樣式**（2026-09-23 起；沒有樣式切換，也沒有 `localStorage` 偏好）：`□ ○ ◇` 男／女／性別未知（**實心 `■ ● ◆` 只用在本人**）、`─ │ ┬ ┴ ┼ ┌ ┐`、本人箭頭 `→`。這些字元和 CJK 一樣在中文等寬字型（細明體等）下算 **2 欄**，渲染器就是按 2 欄排的；年齡與備註是 ASCII，每字 1 欄。
  - ⚠ **對齊要以 HIS 為準，不要看預覽的字元寬度**：預覽的西文等寬字型（`ui-monospace`／Menlo 等）把 □○─│ 當成 1 欄畫，所以預覽把 2 欄字元包成固定 `2ch` 的 inline-block（`.note .pedigree .w2`，橫線再 `scaleX(2)` 拉滿）來模擬中文等寬；複製走 `innerText`，只帶純文字。
- **本人（proband）自動畫在最後**，性別沿用出生區，年齡固定 `NB`，一律加箭頭。母親年齡與 G/P/A 沿用產前區（`#matAge`／`#gravida`／`#para`／`#abortion`），父親年齡在最後核對區另填。
- **本人實心、其他人空心**（2026-09-23 Ryan）：不另標「帶病」；父母的家族史（`S.parent.thal`／`g6pd`／`thyroid`）只接在該側註記後（`Father 35y, G6PD deficiency`），手足與半手足的診斷／症狀寫在各自的「診斷／症狀」欄，畫在年齡下一行。
- **同胎畫分叉**：勾了「同胎」的手足與本人合成一個子代單元，共用一條主幹再分叉；其餘手足各佔一個單元，依出生序由左至右（最年長在前）。
- **父母關係三種線型**（核對區「父母關係」，預設「一般」）：一般＝實線 `───`；未婚＝虛線 `╌╌╌`；離婚・分居＝靠左那位成人符號右緣兩道斜線 `╱╱─`（右半段維持實線）。每段線的中點都是接點 `┬`，子代掛在它底下。
- **父親不詳**：符號改 `◇`，註記寫 `Father unknown`（不寫年齡，父親年齡欄位一併停用），父母關係線照樣畫。
- **父親或母親與其他伴侶的小孩（半手足）**：兩個收合區塊各自有「關係／伴侶年齡／伴侶備註／小孩清單」。成人列由左到右是「父親的其他伴侶（女）－父－母－母親的其他伴侶（男）」，其他伴侶的性別固定（半手足的另一位生物學父母），沒填年齡也沒填備註就不寫註記；小孩掛在各自那段關係線的接點底下，左組在父親左側、右組在母親右側，**各掛各的線**，半手足沒有「同胎」。相鄰成人距離會隨三組子代的寬度一起放大，三組永遠不重疊。只要兩個區塊都沒動過，整棵樹與單一家庭版逐字元相同。
- **沒填的一律省略，不留佔位**：年齡、G/P/A、備註缺了就整段不寫。樹裡永遠不會出現 `__`（複製鈕的「尚有 N 空格」用 `_{2,}` 統計，樹裡有底線會被誤算）。什麼都沒填時仍畫最小樹（父母＋本人）——那是結構，不是捏造事實。
- 只進 Admission，不進 acceptance／plan／procedure。預覽用等寬字型顯示（`.note .pedigree`），複製走 `innerText`，空格會原樣帶走。
- 已知限制：**兩人同胎組**的算術中心落在奇數欄（成員在 18／24 時中心是 21），而 2 欄寬的接點必須與符號同奇偶才接得上，所以接點往左靠一欄畫在 20。線仍然接得上，只是那一段的分叉不完全對稱。

## 填寫介面

- 頂層加入情境設定，其後維持 chart 的產前→出生順序；區分輸入階段但不把病歷改成欄位清單，不改動臨床計算或用藥規則。
- 桌面左側填寫、右側預覽；手機預覽預設收合。放大字級、明確的選取與鍵盤焦點，減少重複框線。
- 手機只有分頁列與合併式位置導覽兩層固定列；高度依實際尺寸量測，欄位定位會避開導覽。不再另固定第三層情境標頭。
- 填寫中「下一段」為主要操作、仍能隨時「複製草稿」；進入核對後切換為「複製病歷」。最後一個子階段直接接核對，第一個子階段可回到出生區；章節選單支援鍵盤與 Escape。
- 一般選項使用同一強調色與勾記；沿用資料採唯讀摘要。臨床篩檢的陽性／陰性仍保留結果文字與色彩提示，不只用顏色傳達狀態。
- 外院照護／轉送選「確認持續同前」後，呼吸模式改為唯讀來源摘要，不再顯示相反的「未記錄」選項；本階段另記裝置／參數可展開，原值保留，未填不推定同前。模式不同請改選「已調整支持」，原有確認失效檢查不變。
- 篩檢直接選擇結果，窄畫面使用原生選單。Rubella「未提及」是中性狀態，不當成陰性。
- 空值本來就合法的單選（性別、生產方式、入院去處、入院路徑、各段呼吸支持與裝置）再點一次已選項目＝取消，手機誤觸不必重整頁面；有語意預設的單選（生長分級、日齡、超音波、產檢）維持不可清空。
- 分頁記住本次開頁的捲動位置，滑鼠／觸控切回時可接續原欄位；鍵盤方向鍵定位分頁，Enter／Space 啟用。可收合區塊也支援鍵盤操作。
- 預覽**預設校閱模式**（Ryan 2026-09-20：醫師編輯時應顯示校閱）：填寫期間看得到自動帶入與未填空格的標記；閱讀模式手動切換給最後通讀。三段字級與兩種模式都只改顯示，不改病歷文字；更新時保留預覽位置並短暫標示變動文字。預覽本身唯讀，不會被鎖住不更新。
- 手機收合後複製仍保留預覽排版的換行（例如家系圖）；複製結果另列提示，不把按鈕擠寬。底部留白隨預覽工具列高度調整。
- 上述位置與預覽偏好只存在本次開頁記憶體，重新整理即重設，不新增病人資料儲存。
- 「本院區」只列台北、淡水、新竹、台東（下拉選單），並在此瀏覽器記住選擇。舊版若曾把其他醫院存成本院區，不再套用該值。
- 產檢地點、出生院所、外接出生院所、轉入來源四欄**可打字搜尋、也可自填**：都是 input 接同一份 `<datalist id="hospList">`，打短名（「惠心」）或全名任一段（「婦產科」「板橋」）都能篩到；清單沒有的院所直接打字即可，原文照寫進病歷、不做正規化。留白依各欄位提示處理；特別是 E 的出生院所留白不推定為本院。
- 院所清單整理自**外接登記主檔的別名表**（常外接的婦幼診所與醫院），四個馬偕院區也在清單內，可當成外院出生地或轉入來源選。清單住在程式碼裡（`HOSPITALS`），短名＝寫進病歷的字、全名只給搜尋與辨識用。舊清單的「三重蕙心」是錯字，已更正為**三重惠心**（惠心婦產科小兒科診所）。

## 檔案 / 建置
- `index.html` — GitHub Pages 部署檔（standalone 完整 HTML，直接開即可用）。
- `_demo_structured.html` — 本體原始碼（body-only，供 Artifact 預覽與編輯）。
- `lab-parse.js` — **共用檢驗/血氣貼上解析器（單一真相）**。原始邏輯來自 `~/nbc-note-app`（病程記錄 App）的 `doLabParse`。Acceptance 分頁的「Other (CBC/DC, CRP…)」欄貼上血檢報告後即用它整理成一行（WBC/DC、Hb、PLT、電解質、腎肝、CRP… 並自動附 I/T ratio）。
- **建置**：`index.html` = HTML 外殼 ＋ `_demo_structured.html`。`lab-parse.js` 的核心函式以 `//__LABPARSE_START__` / `//__LABPARSE_END__` 標記內嵌進 `_demo_structured.html` 的主 IIFE（維持單檔自足）。改動請編輯 `_demo_structured.html`，再重新產生 `index.html` 後 push。
  - ⚠ **改解析邏輯請改 `lab-parse.js`**，再重新內嵌回兩邊（本 app 與 nbc-note-app），勿在各 app 內各自修改而讓兩份漂移。

> **零病人資料**：本 repo 只放程式碼＋README。設計規格、含真實個案的範例（病歷號／院所／個案細節）一律只留本機、不進版控。連 placeholder 都用假值（病歷號 `00000000`）。

## 本機開發
瀏覽器直接開 `index.html` 即可，無需建置環境。

修改 `_demo_structured.html` 後執行 `bash build/build.sh`；`bash build/build.sh --check` 檢查部署檔同步。
在 `tests/prose` 執行 `npm ci`、`npm test`，驗證敘述快照與欄位輸出、預覽唯讀且永遠跟著表單、時間單位文法、Procedure 的已完成／計畫時態，以及篩檢選取、分頁／收合操作、預覽顯示與複製。刻意調整文句時，可用 `npm run update` 更新快照，再檢查 diff；快照使用固定日期，所有案例均為假資料。

### 新版流程驗收

`npm test` 包含 E 模組、日期／DOL 邊界、欄位輸出、路徑草稿、未知與陰性、Admission／Acceptance 時點隔離，以及原有功能回歸。完整對照見 [Admission 欄位對照](docs/admission-field-map.md)。

真實瀏覽器驗收需先啟動獨立測試用 Chrome（CDP port 9333），再於 `tests/prose` 執行 `npm run test:browser`；亦可使用 `node browser-workflow.cjs <測試網址>`。腳本以假病例檢查 1440／1366 px 桌面、320／360／390 px 手機寬度、短視窗及亮／暗主題；包含實際滑鼠命中、原生文字輸入／Escape、複製、合併導覽、返回位置、跨分頁與重複奶量核對。先走混合 E 情境，再重新載入填直接入院 A 與外院轉入 D；另檢查所有 A–D 階段均可操作。截圖與假病歷寫入暫存目錄，須另外目視檢查。這是 Chrome 自動化與手機尺寸模擬，不等同真實住院醫師試用或 iOS／Android 實機驗收，也不保證能辨識任意自由文字的所有矛盾。
